# KORT Presentation System v7.9 — TEMPLATE_SPEC

## Назначение

Single-file HTML-шаблон для презентаций КОРТ. Файл автономный: стили, JS, темы, библиотека слайдов, графики, SVG-иконки и вставленные изображения хранятся внутри одного `.html`.

## Главный принцип

**Demo = Templates 1:1.**  
Каждый демонстрационный слайд в `<main id="deck">` обязан иметь такой же `<template data-layout="...">` во внутренней библиотеке. Если layout есть в демо, он есть в templates. Если layout есть в templates, он показан в демо.

Templates — источник для добавления новых слайдов вручную и для работы LLM/агента. В v7.9 каталог состоит из **22 архетипов**: 22 demo-слайда = 22 templates.

## Canvas и масштабирование

При просмотре в браузере фон слайда растягивается на **весь viewport**: `.slide`, `.deck` и `.deck-shell` занимают `100vw × 100vh`. Это нужно, чтобы на экранах с нестандартным соотношением сторон не появлялись видимые вертикальные границы слайда.

Внутри каждого слайда есть служебный слой `.slide-canvas`: он сохраняет исходную координатную систему **1600×900** и центрируется/масштабируется через `--canvas-scale`. Фон full-bleed, контент сохраняет 16:9 и не обрезается.

Для печати/экспорта применяется фиксированная база **1920×1080**: `.slide-canvas` масштабируется `scale(1.2)`. Агент не должен удалять `.slide-canvas` и не должен менять размеры `1920×1080 / 1600×900 / scale(1.2)` без отдельной задачи на редизайн всей системы.

## Что агент может менять

- Порядок `<section class="slide">` внутри `#deck`.
- Количество слайдов: клонировать, удалять, добавлять из `<template>`.
- Текст внутри `[contenteditable="true"]`.
- `data-chart` у `.auto-chart`.
- `data-icon` у `[data-icon-picker]` из разрешённого icon catalog.
- `data-theme="light|dark"`, если layout это допускает.
- `data-title`, `data-purpose`, если создаётся новая содержательная версия слайда.
- Inline `background-image` у media slots, если изображение встраивается как data URL.

## Что агент не должен менять

- CSS tokens и базовую систему классов без явной задачи.
- JS навигации, сохранения, загрузки картинок, themes, icon picker и chart engine.
- ID системных элементов: `deck`, `overview`, `libraryPanel`, `iconPickerPanel`, `fileInput`, `themeSelect`.
- Структуру `<template data-layout>`.
- Формат `data-chart`.
- SVG-спрайт и ID иконок без задачи на расширение набора.
- Внешние зависимости: шаблон должен работать без интернета.

## Layout catalog

| data-layout | Название | Когда использовать | Ограничения |
|---|---|---|---|
| `cover` | Обложка | Старт презентации, крупный типографический акцент. | Один главный заголовок, короткий kicker, год/квартал. |
| `section` | Раздел | Переход между смысловыми блоками. | 1 крупный тезис + короткий подзаголовок. |
| `statement` | Большой тезис | Один ключевой вывод. | Заголовок до 2–3 строк, пояснение до 2 строк. |
| `principles2` | 2 принципа | Две равноправные идеи по модели “принцип → цель → позиция”. | Не превращать в длинные статьи. |
| `cards3` | Текстовые карточки 3–9 | Гибкая сетка текстовых карточек: направления, проблемы, выводы, принципы. | 3–9 карточек. Одна карточка может быть `primary`. Больше 9 — разбить на два слайда. |
| `icon-cards` | Карточки с иконками 3–9 | Гибкая сетка иконок: принципы, преимущества, категории, роли или короткие выводы. | 3–9 карточек. Иконка помогает различать смысл, но не заменяет заголовок. Для 8–9 карточек текст должен быть особенно коротким. |
| `media-cards` | Карточки с медиа 3–9 | Гибкая сетка карточек с изображением в шапке: кейсы, интерфейсы, варианты решения, визуальные результаты. | 3–9 карточек. Изображение должно быть настоящим визуалом, не декоративной заглушкой. Для 6–9 карточек подписи 1–2 строки. |
| `hero2` | Hero + 2 | Один главный вывод и поддерживающие факты. | Доминанта обязательна; остальные блоки короткие. |
| `hero4` | Hero + 4 | Один крупный акцент + четыре поддержки. | Не использовать для длинного текста. |
| `split-media` | Изображение + текст | Визуал на половину слайда + объяснение. | Это намеренная двухколоночная композиция; текст поддерживает изображение. |
| `wide-media` | Широкое изображение | Крупный скриншот, схема или изображение почти на всю ширину. | Заголовок может быть широким; под визуалом только короткий вывод. |
| `full-bleed` | Фото на весь слайд | Эмоциональный разделитель, кей-визуал или сильное изображение с текстом поверх. | Текст только в безопасной зоне; не перегружать деталями. |
| `stacked-media` | Изображение сверху | Большая картинка сверху, вывод и пояснение снизу. | Для схем и экранов, которым нужен широкий формат. |
| `product-demo` | Desktop demo | Крупный реальный скриншот интерфейса в browser-frame. | Не рисовать fake UI. Вставлять настоящий screenshot. |
| `product-focus` | Product focus | Тёмный слайд: продуктовый экран + один вывод. | Один экран, один смысл. |
| `kpi` | KPI | Одна главная метрика и несколько контекстных цифр. | Главная метрика должна читаться первой. |
| `chart` | График | Data-driven line/bar/donut + 1–2 вывода. | Не рисовать график руками в SVG. Менять только JSON data-chart. |
| `compare` | Было → стало | Сравнение двух состояний. | 3–4 пункта на сторону. |
| `process` | Процесс | Последовательность 3–4 шагов. | Каждый шаг: действие + результат. |
| `team` | Команда | 3 спикера / владельца направлений. | Для 5–6 человек нужен отдельный layout в будущем. |
| `table` | Таблица | Точное сравнение или план. | До 4 колонок, без перегруза. |
| `final` | Финал | Закрытие презентации или переход к вопросам. | Не добавлять новый сложный смысл. |


## Configurable card grids

В v7.9 карточные сетки стали конфигурируемыми. Агенту не нужно создавать отдельные layouts `cards-4`, `cards-8`, `cards-9`. Используется один layout и разное количество дочерних карточек.

Поддерживаемые сетки:

- `cards3` + `.smart-card-grid.text-card-grid` — текстовые карточки;
- `icon-cards` + `.smart-card-grid.icon-card-grid` — карточки с иконками;
- `media-cards` + `.smart-card-grid.media-card-grid` — карточки с изображением в шапке.

Общие правила:

- минимум 3 карточки;
- максимум 9 карточек;
- 3 → 3 в ряд;
- 4 → 4 в ряд;
- 5 → 3 + 2;
- 6 → 3 × 2;
- 7 → 3 + 4;
- 8 → 4 × 2;
- 9 → 3 × 3.

JS автоматически добавляет классы `items-N` и `density-comfortable|compact|dense`. Агенту достаточно клонировать или удалить `article` внутри `.smart-card-grid`; вручную писать `items-N` не обязательно.

Ручной редактор показывает кнопки `⊞` и `⊟` на карточных слайдах. Они добавляют или удаляют последнюю карточку и пересчитывают сетку.

Если нужно больше 9 смыслов, агент должен разделить контент на несколько слайдов, а не делать плотный каталог.

## Типографика и текстовые фреймы

Не ограничивать текст короткой колонкой там, где композиция не является двухколоночной. Для горизонтальных layouts (`statement`, `wide-media`, `product-demo`, `kpi`, `chart`, `process`, `table`) заголовок и lead могут занимать широкую верхнюю зону слайда.

Колонки допустимы только там, где это смысл layout: `split-media`, `product-focus`, `principles2`, `compare`, карточные сетки.

## Chart API

График задаётся через `.auto-chart`.

### Line / donut

```html
<div class="auto-chart" data-chart='{
  "type":"line",
  "labels":["Янв","Фев","Мар"],
  "values":[42,57,79]
}'></div>
```

### Bar с 1–3 сериями

Для bar chart предпочтительно использовать `series`. Максимум — 3 серии, иначе график становится плохо читаемым.

```html
<div class="auto-chart" data-chart='{
  "type":"bar",
  "labels":["Доступ","Онбординг","Поиск","Заявки"],
  "series":[
    {"name":"До","values":[18,27,12,16]},
    {"name":"После","values":[7,11,3,9]},
    {"name":"Цель","values":[6,10,4,8]}
  ],
  "showValues":true
}'></div>
```

Поддерживаемые типы:

- `line` — динамика;
- `bar` — сравнение категорий, 1–3 серии;
- `donut` — доли.

SVG генерируется JS-движком автоматически. Агент не должен руками редактировать SVG path/rect/circle внутри графика.


## Brand logo API

Шаблон поддерживает один глобальный брендовый логотип презентации. Он используется во всех элементах `.brand-logo`, включая обложку, финальный слайд и соответствующие templates.

Пользователь может заменить логотип вручную:

- клик по логотипу на слайде;
- кнопка `Лого` в нижней панели;
- горячая клавиша `L`.

После выбора PNG/SVG/JPG логотип применяется ко всем текущим слайдам и ко всем templates, поэтому новые слайды из библиотеки получают тот же бренд. При сохранении копии HTML логотип остаётся встроенным в файл.

Агенту не нужно заменять логотип в каждом слайде отдельно. Если требуется бренд другого трайба, обновляй глобальный asset через `brandLogoAsset` / `.brand-logo`, не создавай отдельную версию шаблона.

Не хранить логотип внешней ссылкой: для переносимости он должен быть `data:image/...` внутри HTML.

## Icon API

Иконки встроены в HTML как SVG-symbol и вызываются через `<use href="#icon-name">`. В v7.9 используется bulk-набор: **176 системных SVG-иконок**, встроенных прямо в HTML. Иконки перекрашиваются через `currentColor`, поэтому работают с темами и не требуют внешних файлов.

В карточках с иконками агент меняет только `data-icon` и соответствующий `href`:

```html
<button class="icon-button" type="button" data-icon="target" data-icon-picker>
  <svg><use href="#icon-target"></use></svg>
</button>
```

Основные рекомендуемые ID для презентаций: `target`, `star`, `user`, `user-circle`, `users` если он появится в расширенном наборе, `speed-test`, `shield`, `shield-check`, `shield-warning`, `warning`, `check-circle`, `calendar`, `clock-circle`, `agenda`, `notepad`, `presentation`, `browser`, `computer`, `cpu`, `plugin`, `apps`, `layers`, `globe`, `search-01`, `focus`, `filter`, `information-circle`, `help`, `lock`, `money`, `chart` если будет добавлен позже.

Полный каталог доступен в коде шаблона как `const iconNames=[...]` и в ручном picker'е. Если агент сомневается в ID, он должен выбирать только из `iconNames`, а не придумывать новые.

Не использовать внешние SVG-файлы и не вставлять растровые картинки вместо системной иконки. Если нужно добавить новый icon pack, расширять SVG sprite и `iconNames`, не менять API карточек.

## Media API

Слоты для изображений помечены `data-click-upload`. Пользователь может вставить картинку вручную. JS сжимает изображение и сохраняет его как `data:image/...` внутри HTML. После `S` / кнопки сохранения файл остаётся автономным.

Агенту нельзя подменять медиа на внешние ссылки, если нужна переносимость файла.

## Themes

Тема выбирается через `body[data-palette]`:

- `aurora` — основная зелёно-фиолетовая;
- `deep` — более тёмная и насыщенная;
- `clean` — более светлая и спокойная.

Фирменные зелёный и фиолетовый сохраняются во всех темах.

## Portability requirement

Финальный результат должен быть одним `.html` файлом. Он должен открываться локально, сохранять встроенные изображения и иконки, позволять менять порядок, дублировать, удалять и добавлять слайды из внутренней библиотеки без доступа к исходному шаблону.
