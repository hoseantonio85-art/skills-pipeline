# Граница UX и UI

## 1. Зачем нужна граница

Граница нужна, чтобы второй этап не начал преждевременно рисовать и кодировать
решение, а третий этап не восстанавливал логику по красивому макету.

## 2. Разрешено на UX-этапе

### Сценарий

- шаги;
- развилки;
- точки входа;
- выходы;
- возвраты;
- подтверждения.

### Информация

- сущности;
- данные;
- приоритет;
- summary;
- meta;
- детали;
- связи;
- evidence.

### Взаимодействие

- page;
- modal;
- drawer;
- inline block;
- assistant;
- раскрытие;
- фильтрация;
- выбор;
- подтверждение;
- отмена.

### Поведение

- состояния;
- feedback;
- ошибки;
- пустые состояния;
- loading;
- доступность действия;
- последствия.

### Смысл текста

Можно определить:

- назначение сообщения;
- смысл primary action;
- тип предупреждения;
- причину внимания;
- обязательное объяснение.

Допустимо предложить рабочие формулировки, если они влияют на понимание
сценария. Они не считаются финальным UI copy.

## 4. Пограничные случаи

### Можно выбрать modal или drawer

Это UX-решение, потому что выбор связан с намерением пользователя и глубиной
сценария.

### Нельзя задавать ширину modal

Это UI-решение.

### Можно описать порядок смысловых зон

```text
summary → причины → влияние → связи → детали
```

### Нельзя рисовать их расположение

Нельзя задавать колонки, размеры и визуальную сетку.

### Можно указать, что действие должно быть постоянно доступно

### Нельзя определять точный визуальный компонент

## 5. Handoff третьему этапу

UX передаёт:

- список surfaces;
- назначение;
- порядок смысловых блоков;
- действия;
- переходы;
- состояния;
- данные;
- ограничения;
- текстовые намерения;
- traceability.

UI-прототип определяет:

- визуальную композицию;
- UI Kit components;
- размеры;
- токены;
- внешний вид;
- интерактивную реализацию.
