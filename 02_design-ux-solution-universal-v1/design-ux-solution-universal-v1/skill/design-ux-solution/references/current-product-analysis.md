# Анализ текущего продукта

## 1. Задача анализа

Текущий продукт изучается не для механического копирования интерфейса, а чтобы
понять:

- где живёт сценарий;
- как пользователь входит в него;
- какие сущности и термины уже знакомы;
- какие действия уже доступны;
- что нельзя сломать;
- что является легаси;
- где находится причина текущей проблемы.

## 2. Минимальный AS IS

Опиши:

1. точку входа;
2. роль;
3. последовательность действий;
4. доступные данные;
5. решения пользователя;
6. системную обратную связь;
7. связанные сервисы;
8. основные трудности;
9. неизвестные.

## 3. Continuity map

Используй таблицу:

| Элемент текущего продукта | Решение | Причина | Evidence |
|---|---|---|---|
| ... | сохранить / изменить / удалить / проверить | ... | ... |

### Сохранить

То, что:

- поддерживает ментальную модель;
- используется другими сценариями;
- подтверждено как полезное;
- необходимо для совместимости.

### Изменить

То, что:

- создаёт проблему из brief;
- усложняет решение;
- противоречит продуктовым принципам;
- мешает приоритизации или действию.

### Удалить

Только если:

- функция дублируется;
- шаг не несёт ценности;
- нет обязательной зависимости;
- решение подтверждено владельцем.

### Проверить

Когда evidence недостаточно.

## 4. Не переносить легаси автоматически

Наличие текущего паттерна не доказывает его правильность.

Для каждого значимого элемента спроси:

- помогает ли он пользователю понять ситуацию;
- помогает ли принять решение;
- соответствует ли новой задаче;
- является ли ограничением или просто исторической реализацией.

## 5. Если доступна кодовая база

Используй её для проверки:

- фактических точек входа;
- маршрутов;
- состояний;
- имен сущностей;
- существующих действий;
- интеграций;
- ошибок и loading states.

Не используй код для определения визуального решения.

## 6. Если доступны скриншоты

Извлеки:

- структуру;
- порядок информации;
- действия;
- текущий flow;
- видимые состояния;
- проблемы и несогласованности.

Не делай выводов о скрытых правилах.

## 7. Если AS IS отсутствует

Зафиксируй один из режимов:

- `documented-only`;
- `owner-described`;
- `target-state-by-choice`;
- `unknown-blocking`.

Не скрывай отсутствие AS IS.
