# Пример фрагмента UX-решения

> Пример показывает уровень детализации, а не факты конкретного продукта.

## Центр сценария

| Элемент | Описание |
|---|---|
| Триггер | Система обнаружила изменение состояния объекта |
| Главный сигнал | Объект требует внимания |
| Вопрос пользователя | Почему ситуация изменилась и нужно ли реагировать |
| Решение | Принять предложенную реакцию, отложить или не согласиться |
| Действие | Запустить действие или зафиксировать решение |
| Feedback | Система подтверждает решение и показывает новое состояние |

## Архитектура взаимодействия

```text
приоритетный список
→ modal объекта
→ drawer быстрого действия
→ подтверждение
→ обновлённое состояние объекта
```

Обоснование:

- список нужен для приоритизации множества объектов;
- modal нужен для понимания объекта и решения;
- drawer используется для короткого действия без потери modal-контекста.

Это UX-описание. Оно не задаёт размеры, цвета, сетку и компоненты.
