# Design UX Solution

## Результат

Создай UX Solution, по которому следующий этап сможет собрать прототип без повторного изобретения сценария. Основной объём документа посвяти решениям: что предлагается, почему и как это помогает пользователю.

Перед началом прочитай:

- утверждённый Product Task Brief;
- foundation и затронутые services;
- `03_ux/ux_principles.md`;
- релевантные sections `03_ux/ux_patterns.md`;
- при выборе modal/drawer — соответствующие pattern references.

Не пересказывай brief. Дай компактную traceability-ссылку на его цели и ограничения.

## Рабочий процесс

1. Сформулируй UX-задачу одним абзацем.
2. Определи момент входа, контекст пользователя и критерий завершения.
3. Построй journey: этап, намерение, информация, действие, системный ответ, риск.
4. Опиши happy path и значимые альтернативные сценарии.
5. Определи сущности, состояния и отношения между ними.
6. Расставь информационные приоритеты: сигнал → смысл → действие → детали → meta.
7. Выбери surfaces по намерению пользователя и обоснуй выбор.
8. Определи переходы, сохранение контекста и возврат.
9. Покрой loading, empty, error, partial, success и action progress там, где они релевантны.
10. Определи роль AI: входы, ценность, неопределённость и человеческое решение.
11. Подготовь structural handoff для визуального прототипа.

## Выбор surfaces

Не начинай с компонента. Сначала определи задачу поверхности.

- Page — самостоятельная работа, обзор или устойчивый контекст.
- Card registry — основной способ представить множество объектов NORM с приоритетом и объяснением.
- Dashboard — обзор ситуации, мониторинг, сравнение и поиск зон внимания; используй, когда агрегаты действительно ведут к исследованию или действию.
- Object Modal — просмотр или работа с самостоятельным объектом без потери исходного множества.
- Drawer — подчинённая задача, фильтры, настройка, выбор, пояснение или дополнительный слой внутри текущего контекста.
- Inline/expand — короткая локальная деталь или действие.

Классическую таблицу не используй как основную поверхность объектов. Для больших множеств проектируй структурированные строки-карточки. Локальная табличная сетка допустима для истории изменений или сравнения однородных значений.

## Формат результата

Используй `references/ux-solution-template.md`. Обязательные разделы:

1. UX-задача и принципы решения.
2. Rationale ключевых решений.
3. Journey map.
4. Happy path.
5. Альтернативные сценарии и развилки.
6. Сущности и информационная модель.
7. Information hierarchy.
8. Surfaces и переходы.
9. Состояния и feedback.
10. Роль AI.
11. Structural handoff.
12. UX acceptance criteria.
13. Предположения и вопросы.

Structural handoff должен перечислять для каждой surface: назначение, вход, главную информацию, действия, состояния, переходы и сохраняемый контекст. Не задавай цвета, пиксельные размеры и конкретные компоненты UI Kit.

## Quality gate

Решение готово, если оно:

- меняет проблемный сценарий из brief;
- содержит journey и завершённый happy path;
- объясняет ключевые проектные решения;
- не заставляет пользователя вручную собирать главный вывод;
- сохраняет контекст между списком и объектом;
- покрывает важные развилки и состояния;
- даёт достаточный handoff для HTML-прототипа;
- не маскирует повтор требований под UX-анализ.

Статусы: `NEEDS_UX_DECISION`, `READY_FOR_PROTOTYPE`, `BLOCKED_BY_CONTEXT`.
