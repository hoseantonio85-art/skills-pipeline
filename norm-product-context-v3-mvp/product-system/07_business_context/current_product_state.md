## Что подтверждено документацией

- связи между сервисами;

- backend repositories;

## Правило для design-ux-solution

Текущие документы можно использовать, чтобы:

- сохранить продуктовую модель;
- выбрать релевантные UX principles;
- не создавать изолированный сервис;
- понимать ожидаемый тип взаимодействия;
- определить связанные сервисы.

Их нельзя использовать как доказательство:

- существования конкретного экрана;
- фактического расположения действий;
- production-полей;
- реализации edge cases;
- доступных прав;
- полного AS IS flow.

## Task-specific evidence

Для задачи можно приложить:

- скриншоты;
- видео или описание flow;
- путь к локальному frontend;
- ссылки на релиз;
- аналитику;
- описание владельца продукта.

Skill должен добавить их в sources конкретного increment, а не превращать в
канонический контекст автоматически.
